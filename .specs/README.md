# Specs do projeto

Cada mudança deve ter uma spec com quatro partes:

- **Contexto:** por que a mudança é necessária e qual problema resolve.
- **Tarefa:** o comportamento ou resultado esperado.
- **Regras:** restrições técnicas, de negócio e de escopo.
- **Definição de pronto:** critérios verificáveis para considerar a mudança concluída.

A pasta `.specs/` só deve entrar no contexto de trabalho quando o agente for instruído explicitamente a ler a spec relevante. Ao receber essa instrução, o agente deve ler a spec antes de planejar ou implementar a mudança.
